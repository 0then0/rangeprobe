RangeProbe in the browser

Can this file be read in parts, as this browser sees it? The page sends a few single-range requests and compares the bytes with your local copy.

How it works

  • Requests go from this browser straight to the URL. No proxy, no account, no cookies (credentials: omit).
  • The reference file is never uploaded or loaded whole: only the slices that match each response are read.
  • A cross-origin server must allow this page with CORS. If it does not, the browser hides the response and the page can only show that fetch() failed.

http or https. Query parameters are kept in the request and can be redacted in the report.

A local copy of the published file. It is assumed to be byte-identical; the page cannot check that.

Planned requests

    Limits

    Fixed: 5 requests (8 at most), 2 MiB per response, 8 MiB in total. A server that ignores Range is read for 64 KiB at most, then the transfer is cancelled.

    Results

      Report

      The JSON report holds the URL, the origin of this page, the ranges, statuses, readable headers, byte counts and comparison results. It does not contain the reference file or any response body.

      What a page cannot see
      • Raw bytes. The browser sets Accept-Encoding and decodes content codings before the page reads the body. The page compares the bytes it receives, which equal the bytes on the wire only when no coding was applied.
      • Headers of cross-origin responses. Only CORS-safelisted headers and those the server lists in Access-Control-Expose-Headers are readable. A missing Content-Range may be absent or merely hidden; the page cannot tell.
      • Why a request failed. A rejected fetch() names no cause. CORS, a rejected preflight, DNS, TLS, mixed content, an extension and being offline look alike. A suffix range (bytes=-N) needs a preflight that the other ranges do not.
      • Redirects and protocol details. The browser follows redirects itself; the page sees only the final URL.
      • Whether the reference is the right file. A difference means the bytes differ, not that the server is broken.
